# 评测协议

## 作答条件

固定数据校验值、split、模型版本、系统提示、工具权限、采样参数、输出 token 上限、重复次数与失败重试策略。主报告采用每题一次最终作答；重试只处理传输失败，必须同时报告全部尝试与消耗。`closed_book` 只提供题面；工具辅助实验单独报告并列明工具和外部访问范围。

推荐以 test 的 55 题为固定最终集合；dev 的14题用于接口与提示调试，validation 的12题用于选择设置。不得根据 test 成绩反复调提示后仍宣称独立测试。切分先按 `family_id` 的固定哈希分配，再将缺失测试等级的整个最小题族移入 test（同大小按固定哈希排序）；确保测试覆盖全部8级。该规则只使用题面标注，未用模型成绩。同一 `family_id` 不跨 split；来源题号或主题相同仍可能存在较弱语义关联，题族切分不等于无污染保证。

## 统一评分

每题总分4，评分点数量与分配按各题数学任务确定。常见为1+2+1，含多个独立子问的题可为1+1+1+1；评卷必须读取该题的全部评分点键与上限。评分者允许不同的正确证法。核心数学错误使总分至多2；满分且没有核心错误才标为 `fully_correct=true`。题目要求证明时，仅结论、题面复述、有限数值实验均不能作为完整证明。

汇总包括严格全对率、归一化得分、分难度/难度段/主题得分及按评分点计算的能力代理分。空分组输出 null，不作0分填充。难度宏平均只在全部8级都有样本时给出；小规模高难度组尤其要同时展示分母。

## 自动评卷

`auto_evaluate.py prepare` 在评分端加载参考解答和模型回答，绑定题目、回答、提示的 SHA256。对每份有效回答生成两次独立请求，两种提示分别检查正向推导与反例/边界。两次请求互不读取对方输出；仅更换提示不等于统计独立，指定不同评卷模型也无法排除共同偏差。

评卷返回严格 JSON（下面是三评分点题的示例；四评分点题还必须含C4）：

```json
{"criteria":{"C1":1,"C2":2,"C3":1},"fully_correct":true,"critical_error":false,"reference_issue":false,"rationale":"逐项说明证据和条件核查。"}
```

两次评分点、全对标志与核心错误标志完全一致且没有参考疑点时，产生 `automatic_agreement`。分歧、参考疑点、缺失/不合法的评卷输出产生 `needs_review`，不能静默算成模型错误。汇总的上下界把未决项分别按0和满分计算，这**不是统计置信区间**。缺失回答、空回答、求解器错误为已确定0分，保留在固定分母中。评卷失败与求解失败采用不同语义。

`run_solver.py` 只接受四字段白名单；它不会打开金标准。不要将完整仓库或解答目录挂载给封闭求解器。运行目录必须与原 manifest 完全一致才能续跑；更改模型、端点、提示或预算后使用新目录。返回 `length`、不合法 JSON 或评分超界均不会被当作正常完成。

## 人工复核

正式人工汇总命令：`python tools/evaluate.py human_grades.jsonl --split test --output runs/human_report.json`。

每行须包含：`id`、`status="adjudicated"`、`review_type="human"`、至少两个不同的非空 `reviewer_ids`、`response_sha256`、`criteria`、`fully_correct`、`critical_error`、`rationale`。必须覆盖整个切分。SHA256应由审阅者和实际答卷逐一核对；单独的人工汇总工具检查其格式，不替代答卷来源审计。工具不把自动评分改写成人工裁决。

如报告 Wilson 区间或探索性比较区间，须说明题目不是独立同分布抽样，小组与题族关联可能使常规区间过于乐观。固定题库分数首先是描述统计，不是未来所有概率论题目上的能力保证。

## 可执行核查

23项离线测试覆盖：全库结构和导出一致性、分题族切分、schema类型错误、响应白名单、评分分歧、评分异常、缺答固定分母、篡改/重复/续跑检测、本机模拟HTTP端到端流程；多评分点和非均匀权重兼容；以及随机和联合独立性反例、一阶矩有界不推出一致可积的反例、非对称两点分布的零偏恒等式、带零质量单元的熵链式法则、Bell小规模计数、有限事件协方差界、重叠模式等待时间、Cantelli取等分布、两两独立CLT反例的有限块、无穷乘积极限的误差界抽查。它们验证实现及部分数学计算，不是81道证明的形式化验证。
